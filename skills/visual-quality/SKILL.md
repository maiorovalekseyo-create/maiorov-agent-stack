# Visual Quality

Before changing UI:
- read DESIGN.md;
- inspect approved references and existing approved implementation;
- identify the intended visual character;
- preserve unrelated approved areas.

Rules:
- approved reference > agent taste;
- project-specific visual language > generic SaaS patterns;
- mobile is designed, not merely compressed desktop;
- motion supports hierarchy and experience;
- WOW means distinctive coherence and polish, not gratuitous effects;
- use project imagery/assets before generic stock;
- do not silently redesign while fixing one component.

For a new project, create/update DESIGN.md with typography, palette, spacing, materials, motion, imagery, desktop/mobile rules, and "do not" constraints.
